## 1 项目范围与首版规则

首版用一个预置城市、约 20 个景点和 2–5 天的旅行完成演示。每个景点包含名称、坐标、简介、预计停留分钟、参考门票和单个每日开放时间段。用户可以修改停留时长，所有价格和交通时间均标注为演示参考数据。

| 功能 | 首版明确做到 |
|---|---|
| 旅行管理 | 创建、改名、修改开始日期和天数、保存、重新打开、删除 |
| 景点浏览 | 列表与详情，按名称或分类筛选，加入指定日期 |
| 行程编排 | 同一天拖动排序，跨天移动，删除行程项，设置每天出发时间 |
| 时间安排 | 根据顺序、停留时长和预置交通时间重新排时间，提醒开放时间和当天结束时间冲突 |
| 预算 | 汇总门票、预置交通费及用户填写的住宿餐饮等费用，超过预算上限时提示 |
| 路线展示 | 用本地示意画布画出景点位置、编号和连线，显示当前日期的访问顺序 |
| 完整交付 | 空状态、错误提示、刷新恢复、测试数据、运行说明和可复现演示 |

首版以单个演示用户操作，先用普通页面完成主要流程。路线图使用归一化坐标和连线展示，旁边注明示意路线。真实地图、实时票价、自动路线优化和多人协作可排入后续待办。

统一规则在对应功能开发前写入项目定义：

1. 每天默认 09:00 出发、21:00 结束，可调整。同一景点在同一天只允许加入一次，跨天可重复。
2. 按“上一项结束时间 + 相邻景点交通分钟”计算下一项到达时间。当天首个景点交通时间取 0，并标注这是从首个景点开始的安排。
3. 到达早于开放时间时自动等待。游玩结束晚于关闭时间时提示冲突。当天结束时间超限也提示，用户仍可保存草案。
4. 使用一份固定交通时间与费用表。缺失数据时显示待补全，依赖该数据的后续时间标为待计算。
5. 金额用整数分计算。预算为所有天的门票和交通费，加用户录入的其他费用。增删和排序后立即重算。
6. 减少旅行天数前，若被删日期有行程或费用，展示影响并要求确认。确认后按同一操作删除相关内容。

## 3 模块怎么交接

技术栈已接受并采用Vue 3、TypeScript、FastAPI与SQLite。排序可以用适配对应前端框架的拖拽组件，业务状态由项目统一维护。

| 数据 | 最少字段 | 负责人 |
|---|---|---|
| Trip | id、name、startDate、dayCount、budgetLimitCents | 张博涵，杨子游 确认表单 |
| Attraction | id、name、category、x、y、durationMinutes、ticketCents、openTime、closeTime | 张紫萱 准备，张博涵 校验 |
| DayPlan | id、tripId、dayIndex、startMinutes、endMinutes | 张博涵，李乾坤 操作 |
| ItineraryItem | id、dayId、attractionId、order、durationMinutes | 张博涵，李乾坤 操作 |
| OtherExpense | id、dayId、name、amountCents | 张博涵 |
| Transport | fromAttractionId、toAttractionId、minutes、costCents | 张紫萱 准备，张博涵 使用 |

时间用当天分钟数保存，例如 09:00 为 540。行程项保留稳定 id，拖动改变归属与顺序。抵达、离开、等待和冲突由统一计算函数产生，重新打开旅行时按同一规则计算。

接口建议由 张博涵 在第一天补齐请求和响应示例：

- GET /attractions 返回预置景点。
- POST /trips 创建旅行。
- GET /trips 列出已保存旅行。
- GET /trips/{id} 加载完整旅行。
- PUT /trips/{id} 原子保存旅行、日期、行程项和其他费用。
- DELETE /trips/{id} 删除旅行及其相关数据。

前端统一串行保存，可合并连续编辑的待保存快照。显示保存中、已保存或保存失败状态。保存失败保留当前编辑并允许重试，加载失败显示原因。后端保存时验证日期范围、景点引用、顺序和金额，在事务中完成整次更新。

杨子游 加入景点后更新共享行程状态，李乾坤 的卡片立即出现，张博涵 的计算结果刷新，张紫萱 的图示随之更新。在独立模块具备联调条件后，四人按职责联合验证该数据链。

## 6 过程职责和风险

迭代开始共同确认目标、容量和任务，实际工作日同步进展与阻塞，达到演示条件时评审并回顾。李乾坤 当天记录实际问题、责任人、处理和复测结果，回顾选一项下轮能验证的改进。每项完成后需经过队友评审、相关测试和 杨子游 的故事验收，更新对应文档并关联提交。

| 风险 | 触发信号 | 处理与负责人 |
|---|---|---|
| 拖动导致顺序错乱 | 卡片丢失、图示不同步 | 李乾坤 统一状态和稳定 id，张紫萱 复测；阻塞时先提供上移下移及移到指定日的操作完成同一业务 |
| 张博涵 工作量超出容量 | 计算与保存任务同时延期 | 李乾坤 在站会调整任务，张紫萱 承接交通查表；优先完成可验收的主链 |
| 时间规则理解不一致 | 同一行程出现不同预期 | 杨子游、张博涵、张紫萱 用三个手算样例确认规则并写入测试 |
| 保存覆盖新编辑 | 重开后顺序回退 | 张博涵 与 李乾坤 验证保存队列、重试和最终快照 |
| 功能不断增加 | 核心故事未通过又新增地图等接入 | 杨子游 调整待办优先级，团队按剩余容量评估 |

AI 赋能由每位成员结合实际任务留证。杨子游 用 AI 检查用户故事歧义，李乾坤 用于交互异常清单，张博涵 用于手算样例与算法思路核对，张紫萱 用于补充边界测试。记录工具、输入摘要、采纳及修改、人工验证结果，不直接把生成内容记为完成成果。
