# 会议记录格式建议

推荐用Markdown作为日常记录主文件，会议中当天填写并随项目提交GitHub。它支持表格、链接和版本差异，队友可在PR里评审。提交作业时可按老师格式汇总为PDF。

## 文件约定

YYYY-MM-DD_计划会.md、YYYY-MM-DD_每日立会.md、YYYY-MM-DD_评审回顾.md。同一天多场可加序号。AI辅助评审准备使用YYYY-MM-DD_AI辅助开工评审.md并注明辅助方式与待确认情况。

## 每份记录必填

会议日期、类型、主持与记录人、出席成员与人数、迭代与目标、讨论问题、决定及原因、行动项负责人和截止、关联任务与提交、未解决问题、确认情况。

## 适合不同格式的内容

| 格式 | 用途 |
|---|---|
| Markdown | 会议、决策、回顾、风险及AI记录 |
| JSON | 稳定的数据与接口样例，供代码复用 |
| CSV或看板字段 | 工时、任务、度量的统计 |
| PNG或截图 | 演示及缺陷证据，正文链接引用 |
| PDF | 阶段归档和最终提交 |

## 模板

~~~text
会议日期：
会议类型与迭代：
主持／记录：
实际出席：杨子游（3023207120）、李乾坤（3024244468）、张博涵（3024244457）、张紫萱（3023208031）
出席人数：4人
目标：
讨论与决定：
行动项（编号、负责人、截止、验收）：
阻塞与未决：
关联任务、提交和证据：
确认情况：
~~~

每日立会用简短表格记录昨天、今天和阻塞即可。避免复制相同内容形成空日志；缺陷复测和改进验证应链接到实际结果。

## 小组记录统一格式

现有会议的出席按小组本次确认统一为四名成员。后续会议模板按四人团队预填，记录会议日期、方式、议题、决定和行动项，成员或人数有变化时按实际更新。
