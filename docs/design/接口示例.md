# 第一轮接口约定草案

状态为第一轮原型接口已通过验收，完整接口契约继续随迭代完善。完整请求与响应样例见 api-examples.json，完整旅行见 trip-example.json。API统一前缀/api/v1，UTF-8 JSON，使用code、data或message和fieldErrors。

| 接口 | 输入 | 成功 | 失败 |
|---|---|---|---|
| POST /trips | name、startDate、dayCount、budgetLimitCents | 201返回TRIP_CREATED及完整旅行 | 400 VALIDATION_ERROR |
| GET /trips/{id} | 路径id | 200返回TRIP_LOADED及完整旅行 | 404 TRIP_NOT_FOUND |
| PUT /trips/{id} | 完整输入快照，baseRevision | 200返回TRIP_SAVED及完整旅行、新revision | 400非法数据、404不存在、409版本过期 |

保存请求使用baseRevision，响应使用revision。服务端校验所有日程归属、id、顺序和引用，任一项失败则整体回滚。日期、金额、限制沿用需求文档。

接口前端与服务端第一个联调检查为：创建三天得到三条默认日计划，保存排序后再GET得到相同顺序。

## 共同依赖接口

GET /attractions提供keyword、category筛选和景点详情字段，GET /transport返回交通与数据版本，GET /trips列出摘要，DELETE /trips/{id}携带baseRevision。张博涵需在对应功能开发前补齐样例。

## 错误约定

400返回字段与原因。404保留返回列表和重试入口。409返回currentRevision，暂停自动保存并保留本地草案，重新加载前确认。网络失败进入保存失败并允许重试。创建响应不确定时先列表核对。

样例均为契约示范，当前原型提供可运行API，完整设计契约差异见第一轮验收记录。
