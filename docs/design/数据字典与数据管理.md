# 数据字典与数据管理

日期2026-11-27。数据定义既要说明含义，也要对应可运行样例和保存规则。

| 对象 | 关键字段 | 单位与约束 | 当前实现 |
|---|---|---|---|
| Trip | id,name,startDate,dayCount,budgetLimitCents,revision | id由数据库产生，名称1–50字，日期YYYY-MM-DD，2–5天，预算整数分 | SQLite trips表存id、revision和JSON |
| DayPlan | id,dayIndex,startMinutes,endMinutes | 日序1开始，分钟0–1440且开始小于结束 | 保存在Trip JSON |
| Item | id,attractionId,order,durationMinutes | 稳定id，order从0连续，同日景点唯一，时长1–720 | 已有校验，嵌套类型仍需完善 |
| Attraction | id,name,ticketCents,defaultDurationMinutes | id唯一，门票分、停留分钟 | 4条内置合成数据，spot-1至spot-4 |
| Expense | id,name,amountCents | 非负整数分 | 字段预留，编辑和校验后续实现 |
| Transport | fromId,toId,minutes,costCents | 有方向组合，非负分钟和分 | 第二轮 |

## 数据来源与生命周期

景点为课程合成参考数据。前端获取后显示，选中时写入稳定行程项；后端校验后以事务写入SQLite。计算结果从原始输入派生。参考数据变化应登记版本，并检查已保存景点引用。

数据库travel.db为本地运行产物，由程序首次连接时创建，已被gitignore排除。初次启动无旅行，创建接口生成日期。测试使用临时数据库，退出显式关闭连接后清理。

## 设计与原型样例的关系

原设计trip-example.json使用attraction-001等契约标识。可运行原型使用spot-1等标识，现场联调应使用data/第一轮运行样例.json，避免直接向原型提交设计样例。后续统一标识时登记迁移和回归。
